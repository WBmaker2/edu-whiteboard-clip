# 구현 계획 — M3.1 Flash로 만드는 three.js 3D 게임 3종

- 작성일: 2026-10-19
- 실행 모델: `opencode/minimax-m3.1-flash-free`
- 외부 API 호출 없음. 이 세션에서 직접 구현한다.

## 1. 목표

MiniMax M3.1 Flash가 three.js 3D 구현을 얼마나 잘하는지 **실측 가능한 형태로** 남긴다.
모델이 잘하는 영역(절차적 지오메트리 생성, 애니메이션)과 취약한 영역(정밀 인터랙션, 상태 관리)을
게임 3종으로 각각 검증한다.

| 게임 | 검증하는 능력 | 성격 |
|---|---|---|
| `zoo/` 폴리곤 동물원 | 절차적 지오메트리 조립 + 애니메이션 | 쇼케이스(판정 없음) |
| `molecule/` 3D 분자 빌더 | 클릭 상호작용 + 화학 규칙 + 판정 | 교육 게임 |
| `defense/` 3D 타워 디펜스 | 실시간 상태 머신 + 경로 + 전투 | 아케이드 게임 |

## 2. 구조 원칙

**D1. 게임은 완전 분리.** 세 게임은 `zoo/`, `molecule/`, `defense/` 각각 독립 폴더다.
공유 런타임 의존성이 없어 각 폴더를 그대로 떼어 옮길 수 있다. 엔진 코드(stage)는 게임마다
가져가되 요구사항이 달라(조명/그림자/카메라/재질) 각자 튜닝한다.

**D2. 빌드 단계 없음.** `importmap` + CDN 고정 버전(`three@0.186.1`).
`npm install` 없이 `index.html` 열기만으로 실행된다. 빌드 오류 소지가 원천 제거된다.

**D3. 물리엔진 금지.** 충돌·중력·강체는 전부 직접 계산한다.
외부 물리엔진은 API 표면이 커서 모델이 가장 자주 실패하는 지점이다.

**D4. 렌더 결과를 눈으로 확인한다.** `scripts/shot.mjs`가 각 게임을 헤드리스 브라우저로
띄워 콘솔 오류를 수집하고 스크린샷을 남긴다. 시각 버그(위치가 틀린 오브젝트 등)는
텍스트로는 못 잡지만 스크린샷 한 장이면 드러난다.

**D5. 시간을 지킨다.** 렌더 루프는 `dt`를 클램프하고 게임 로직은 1/60 고정 스텝으로
누적한다. 탭 전환으로 `dt`가 수 초 튀는 사고(좌표가 날아가는 버그의 대표 원인)를 막는다.

## 3. 공통 기술 계약 (모든 게임이 지킨다)

```
three@0.186.1
  import * as THREE from 'three';
  import { OrbitControls } from 'three/addons/controls/OrbitControls.js';
```

- `THREE.OrbitControls` 전역 접근 금지(r125 이후 제거됨). 반드시 위 import 경로 사용.
- `renderer.outputColorSpace = THREE.SRGBColorSpace`
- `renderer.toneMapping = THREE.ACESFilmicToneMapping`
- `renderer.setSize(w, h, false)` — CSS 크기는 CSS가, 버퍼 크기는 JS가 담당. 중복 지정 금지.
- 포인터 → NDC 변환은 `canvas.getBoundingClientRect()` 기준. `window.innerWidth` 금지.
- 히트 판정용으로 **투명 프록시 메시**를 함께 두어 클릭 영역을 넉넉하게 만든다.
- `scene.traverse`로 지오메트리/재질을 dispose하는 정리 함수를 둔다.
- 게임 루프: `renderer.setAnimationLoop` + `dt = Math.min(clock.getDelta(), 0.1)` + 고정 스텝 누적.
- ES 모듈 상대 경로에는 반드시 `.js` 확장자를 붙인다.
- 렌더러가 준비되면 `window.__gameReady = true`를 세팅한다(하네스가 대기 신호로 사용).

## 5. 게임별 설계

### 5.1 zoo/ — 폴리곤 동물원

- **비주얼**: 따뜻한 저녁 정원. 크림 하늘, 황토 바닥, 나무·바위 장식, 파스텔 동물.
- 종 파라미터 테이블(`species.js`): 고양이/강아지/판다/토끼. 몸체 비율, 머리 크기·위치,
  다리 길이·굵기, 귀 형태, 꼬리 유무, 색상 팔레트.
- 조립(`animals.js`): 구·원기둥·원뿔·십면체만 사용. 각 파라미터가 지오메트리로 매핑된다.
- 애니메이션: idle 호흡(몸 y축 스케일 sin), 걷기(다리 회전 sin, 보행 위상), 꼬리 흔들기,
  클릭 시 점프 + 회전.
- 배치: 동물은 중앙에 각자 다른 반지름으로 궤도를 그린다. 궤도 위상·반지름이 개체마다 다르다.
- 상호작용: 종 버튼으로 대표 동물을 교체, "추가"로 개체 추가, "걷기" 토글.
  히트는 투명 구 프록시로 판정.
- 이름표는 CanvasTexture 스프라이트로 렌더한다.
- 판정 로직 없음. 시각 완성도와 조작 반응을 보는 게임.

### 5.2 molecule/ — 3D 분자 builders

- **비주얼**: 어두운 실험실. 청록 네온, 반투명 격자, 발광하는 원자, 밝은 결합 막대.
- 원자(`elements.js`): H/C/N/O. 반지름·색상·최대 결합 수(H 1, C 4, N 3, O 2).
- 목표 분자 4종: 물 H₂O, 메테인 CH₄, 암모니아 NH₃, 이산화탄소 CO₂.
- 조작: 팔레트에서 원자 선택 → 작업대 클릭으로 배치. 원자 클릭 → 선택(발광) →
  다른 원자 클릭 → 결합 생성. 같은 두 원자를 다시 클릭하면 결합 차수 1→2→3 순환.
  결합 클릭 → 결합 삭제.
- 자동 배치(`chemistry.js`): 전자 영역 수(결합 수 + 비공유 전자쌍)로 기하를 정하고
  비공유 전자쌍이 있으면 결합각을 압축한다. H₂O 104.5°, NH₃ 107°.
  압축량은 이분 탐색으로 목표 결합각에 맞춘다.
- 검사: 원자 종류별 개수 + 결합 인접 관계 + 중심 원자가 일치하면 성공. 결과와 해설 표시.
- 판정은 원자 수·인접·중심만 본다. 결합 차수는 표시만 하고 판정에는 넣지 않는다(오판 여지 제거).

### 5.3 defense/ — 3D 타워 디펜스

- **비비주얼**: 어두운 명령판. 청록 그리드, 앰버 적, 크림 발사체.
- 격자 12×9, 셀 1.0. 경로는 웨이포인트 폴리라인. 경로 셀에는 타워를 놓을 수 없다.
- 타워 3종: 고속(좁은 사거리), 강력(넓은 사거리, 느림), 범위(관통 피해).
- 적은 경로를 따라 이동하며 `progress`(이동 거리) 값을 들고 있다. 타워는 사거리 안에서
  `progress`가 가장 큰 적을 겨눈다 → 목표 선택 규칙이 명확해 버그가 없다.
- 발사체는 시각 효과용 구체. 도착하면 피해. 범위형은 반경 내 전체에 피해.
- 웨이브 5개. 처치 시 골드 획득, 타워 설치 비용 차감. 생명이 0이면 패배, 마지막 웨이브
  생존 시 승리.
- UI: 골드/생명/웨이브 표시, 타워 팔레트, 다음 웨이브 버튼(수동 시작 가능), 배속 1×/2×, 리셋.

## 6. 검증 방법

`node scripts/shot.mjs <게임명>` 실행 시:

1. 게임 폴더를 정적 서버로 서빙(임의 포트)
2. 헤드리스 크로미움으로 접속, `window.__gameReady` 대기
3. 콘솔 오류·페이지 예외 수집
4. 게임별 대표 조작 1~2단계 수행(예: 종 교체, 원자 결합, 타워 배치)
5. `docs/shots/<게임명>-<n>.png` 저장
6. 콘솔 오류가 있으면 종료 코드 1

통과 기준: 콘솔 오류 0, 스크린샷에서 오브젝트가 화면 밖에 있지 않음, 조작 후 상태 변화 확인.

## 9. 검증 설계 (개선 편)

3D는 **값이 맞는 것과 화면에 보이는 것이 다릅니다.** 2D는 픽셀 좌표가 곧 결과지만, 3D는 카메라·조명·가림이 결과를 좌우합니다. 그래서 단일 검사만으로는 부족합니다.

- **1층 — 순수 계산.** 브라우저 없이 숫자로 확인합니다. `three`를 Node에서 불러올 수 있어야 하므로 devDependency로 넣고, CDN과 **같은 버전(0.186.1)** 을 씁니다. 수학 함수는 three에 묶이지 않게 유지합니다.
- **2층 — 기하 불변식.** 런타임에 "항상 참이어야 하는 것"을 검사합니다. 좌표 유한성, 개체 간 거리, 표식 돌출 여부, 타워와 길의 관계, 분자 축과 시선의 관계. 위반은 화면 배지로 보여줍니다.
- **3층 — 화면 판정.** 4개 시점에서 캡처하고, 아무 개체도 보이지 않는지 / 시점을 바꿔도 화면이 안 바뀌는지 자동 판정합니다. 한 각도에서만 보이는 요소를 놓치지 않기 위함입니다.

## 10. 구현 후 확인된 사항

계획대로 3개 게임이 모두 만들어졌고, 헤드리스 브라우저 검사에서 콘솔 오류 없이 통과했습니다.
검증 과정에서 계획이 예측하지 못한 문제가 나왔습니다.

- **위치가 "움직일 때만" 갱신되는 전제 조건**이 동물원 전체를 어긋나게 만들었다. 정지 상태의 배치를 보장하는 코드가 필요했다.
- **결합각 계산의 단위 불일치**(도 vs 라디안)가 결합을 180°로 펴버렸다. 상태 메시지에 표시되는 목표 결합각은 올바르게 보여서, 숫자만 보고 통과했다고 판단하기 쉬웠다.
- **3D에서 가려진 부분**(판다의 눈·귀가 머리 안쪽에 묻힌 경우)은 2D 스크린샷에 잡히지 않는다. 카메라를 돌려 여러 각도에서 봐야 한다.
- **분자의 평면 방향**은 결합각과 별개의 문제였다. 각도가 맞아도 평면이 카메라와 수직이면 도형을 읽을 수 없다.

검증 3층을 붙인 뒤에는 **새로운 실제 버그 2건**이 더 나왔습니다.

- `validate`가 이웃 원자를 다중집합으로 비교하지 않아, 중심이 다른 분자를 정답으로 받아들이고 있었습니다.
- 경로 지점이 웨이포인트마다 중복 삽입돼, 적이 방향을 틀 때 한 칸씩 제자리에 머물렀습니다.

두 건 모두 1층 유닛 테스트가 잡았습니다. **순수 로직을 테스트 밖에 두면 회귀를 못 잡는다**는 사례이기도 합니다.

자세한 내용과 코드 위치는 [`../README.md`](../README.md) 의 "모델 성능에서 읽은 것" 절에 정리했습니다.
